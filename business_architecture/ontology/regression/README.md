- `expected.csv` gives each question a status:
  - `answerable`: its queries run on the release.
  - `partial`: the graph part's queries run, and `waits_for` names the rest.
  - `waits:<step or decision>`: no query yet; `waits_for` says what the question needs.
  - `parked:<decision>`: parked by a recorded decision, which counts as green (the decision of 2026-10-05); no query, and `waits_for` says what would unpark it.
- `queries/` holds one SPARQL file per tested part. The first line is the question. A query marked "(must be none)" must return zero rows; every other query must return at least one.
- `run.py` runs the queries against the release (default `../releases/core/2.4.0/core.ttl`) together with the organization module's vocabulary, roles and assignments, the kpi module's vocabulary and measures, the data-product module's vocabulary and data products, the value-stream module's vocabulary and value streams, the system module's vocabulary and systems, the lane module's vocabulary and lanes, the market-data module's vocabulary and series, the placement kinds, the source tiers, the APQC element list, the consumer rules, the measure populations, and the `party` module's vocabulary, code lists, systems, lifecycle and reference parties (MPC and MPLX), and prints the coverage. *2026-11-02:* it also loads the technical-graph module's vocabulary and example graph (the decision of 2026-11-02), and the logical-model module's vocabulary with its made-up example model: ER Studio's export as it is and the annotation layer (the decision of 2026-11-02). `scripts/check.sh` runs it and `test_run.py`.
