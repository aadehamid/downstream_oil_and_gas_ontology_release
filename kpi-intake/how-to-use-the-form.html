How to use the KPI intake form

One form holds one KPI. You fill it in a browser, save it as one answers file, and put that file in a shared folder. The form works offline and sends nothing anywhere.

The ontology is the company's shared model of business terms and their links. This form collects the information needed to add one KPI to it.

Where the files are

The blank form, and the journey of one KPI's answers file.

Open the blank form from the folder the-form. Your answers never go into that folder. They go into an answers file, which moves through four places:

  1. 1DownloadsYour browser downloads the answers file, usually to Downloads.
  2. 21-in-progressYou move the file here after every save.
  3. 32-ready-for-checkThe Business analyst moves it here when the form is filled and the business has signed.
  4. 43-checkedThe Architect moves it here when the check says it is complete.

The answers file is the record. Save it whenever you stop.

Before you start

The shared folder, the people, and one rule for sharing a file.

The Architect sets up the shared folder once and gives the team its location. If you already have that location, go to Start a new KPI. The Architect's steps are in For the Architect.

The name of an answers file

Keep the name the form gives. It is the KPI's name in small letters, then .kpi-intake.json. For the KPI "Crack Spreads Pricing" the form proposes:

crack-spreads-pricing.kpi-intake.json

One person at a time

One KPI has one file. One person edits a KPI's file at a time. Agree who has it next. Each person loads the latest file from the shared folder before editing, and puts the new file there in place of the older one. The shared folder keeps the latest file only. It keeps no history of earlier answers or earlier check reports.

The people

Before the interview, open the form's tab "The roles". It says what each role does. Find out who fills each role for this KPI. Ask the Program manager for the request number and its date.

Start a new KPI

From the blank form to the first answers.

  1. Open the-form in the shared folder and double-click kpi-intake-form.html. It opens in your browser.
  2. Select the tab "KPI intake". If it contains earlier work, save that work first. Press "Clear this form", then "Clear", before you start the new KPI.
  3. Open "Request details" at the top. Fill in the request number and date that the Program manager gave you.
  4. Complete sections 1 to 6 with the people named beside each question. Each question says who answers it and why it is asked, and shows an example answer.
  5. Where a question offers a list, choose from the list. You can choose an entry marked "new, not yet in the ontology".
  6. Save when you stop.

If the right answer is not in a list

Choose the last option of the list. It is named "Not in the list", "The step is missing", "A role that is not in the list" or "A document that is not in the list". Write the missing name where the form asks for it.

If a notice then sends you to "Domain activation" or "Process map request", save the KPI file first. Complete the named form and save it separately: it has its own file. Give both files to the Architect. Go on with the KPI after the Architect confirms that the missing item is ready.

Save

The form asks your browser for a download. You put the file in the shared folder.

  1. Press "Save answers to file".
  2. If your browser asks where to save, choose 1-in-progress in the shared folder. If it does not ask, it puts the file in its download folder, which is usually Downloads.
  3. Read the message above the buttons. It names the file.
  4. Check that the file is where you expect. If it is in Downloads, move it to 1-in-progress, in place of the older file of that KPI.
Download requested: crack-spreads-pricing.kpi-intake.json. Check that the file appears in your chosen folder.

The form cannot see whether the download arrived, so look for the file yourself. If Downloads already holds a file of the same name, your browser may add a number such as (1) to the new one. Move the newest file and take the number out of its name.

Continue later

Load the saved file. The browser's draft is a second chance, not the plan.

Before you stop, save the answers file to the shared folder. To continue, open the form and load that file. This works on any computer.

  1. Open the form from the-form.
  2. If the form contains work you need to keep, save it first. Loading replaces the answers for the form held in the file, and does not ask first.
  3. Press "Load answers file" and choose the file in 1-in-progress.
  4. Read the message above the buttons. It says "Loaded" and the file's name. If it says answers were left out, keep the original file and ask the Architect before you replace it.
  5. Go on with the questions, then save again.

The browser's draft

The browser may also restore a local draft. The form tries to keep one as you type. When you open the same form file again in the same browser, your answers may be back, and the form then says:

Your unsaved draft was restored from this browser.
  • The draft is not shared with your team. Someone who uses the same browser profile may see it.
  • Another computer and another browser do not have it.
  • The browser may refuse to keep it, for example in a private window, and the form does not tell you. It goes when someone clears the browser's data.
  • When you clear the form or load a file, the earlier draft of that form is gone.

The three buttons

At the bottom left on a computer, or along the bottom on a phone.

Save answers to file
Asks your browser to download one file with every answer, signature and comment of the open form. The form and the draft stay as they are.
Load answers file
Asks you for a saved file. It opens the form named inside that file and replaces that form's answers. It does not ask first. The saved file is not changed.
Clear this form
Asks "Clear this form?" first. "Clear" removes the earlier entries of the open form and restores its starting values, such as the status "Draft". "Cancel" keeps everything. A saved file is not changed.

Three tabs are forms: "KPI intake", "Domain activation" and "Process map request". Save and Clear work on the open form. Load opens the form named inside the saved file and replaces that form's answers. The other forms keep their answers.

Hand over

From the business interview to Digital IT, and then to the Architect.

  1. Complete sections 1 to 6 with the people named beside each question.
  2. Ask the Data Owner and the Domain Owner to sign. Each signature is a name and a date in the sign-off block.
  3. Save the file and put it in 1-in-progress.
  4. Ask Digital IT to load that file, complete section 7, save it, and put it back in 1-in-progress.
  5. The Business analyst checks that every section's line says "Required answers complete", then moves the file to 2-ready-for-check and tells the Architect.

What the Architect does

The Architect checks the answers first. The check lists each thing that is still open.

  • If answers or business signatures are missing, the Architect returns the file and its report to 1-in-progress.
  • If only the Architect's approval remains, the Architect reviews, signs, saves and checks again.
  • When the check says "the intake is complete and signed", the Architect moves the file and its report to 3-checked.

The check's commands are in For the Architect.

Fix a returned file

If the Architect returns a file, open its report in 1-in-progress. The report's name ends in .check.txt. Load the matching answers file, resolve the listed items, save, and move the file to 2-ready-for-check for another check.

What "complete" means

  • Every required question that applies has an answer.
  • No answer sends the request somewhere else first: to a domain activation or to a process map request.
  • The KPI's name is not already a measure in the ontology.
  • Every signature the form needs has a name and a date.

Find a checked KPI

What is in 3-checked, and what it proves.

To find a checked KPI, open 3-checked. Find its answers file by the KPI's name. Open the matching .check.txt file to read the check's result. To read the answers, open the form and load the answers file.

A file in 3-checked means the intake passed its check. It does not prove that the KPI is already in the ontology. The Architect adds the KPI by hand afterwards. Some answers have no place in the ontology yet and stay in the file, so keep every file in 3-checked.

If you prefer Excel

The same form as a workbook.

kpi-intake-form.xlsx has the same questions and lists. Copy it to 1-in-progress first. Name the copy after the KPI and end the name with .kpi-intake.xlsx. Then fill in the yellow cells and save as usual. The check reads a workbook the same way as an answers file. Use one of the two for a KPI, not both: the HTML form cannot load a workbook.

If something goes wrong

Three things that happen, and what to do.

A file will not load

The form says "This file is not a KPI intake answers file" and gives the reason. Your answers on screen are not changed. Check that you chose a file whose name ends in .kpi-intake.json, and not the report or a workbook. If it is the right file, give it to the Architect.

The form opens with someone else's answers, or with an older KPI

The browser has restored a draft. If that work is not saved, press "Save answers to file" first. Then press "Clear this form" and "Clear", or load the file you want.

A role, a system or another entry is missing from a list

Follow If the right answer is not in a list, and tell the Architect. The Architect can add the entry to the form's lists. The form then offers it, marked "new, not yet in the ontology".

For the Architect

The commands. Each runs from the release's top folder and needs Python.

Make the shared folder

This command makes KPI-intake inside the location you name, with its four folders, and copies the two forms and this guide into the-form. The dot means the current folder.

py -m kpi_store.intake folders .
made KPI-intake/the-form
made KPI-intake/1-in-progress
made KPI-intake/2-ready-for-check
made KPI-intake/3-checked
copied KPI-intake/the-form/kpi-intake-form.html
copied KPI-intake/the-form/kpi-intake-form.xlsx
copied KPI-intake/the-form/how-to-use-the-form.html
wrote KPI-intake/READ-ME.txt
KPI-intake is ready

For a shared drive, name its location in place of the dot. Put it in quotes when it has a space:

py -m kpi_store.intake folders "S:/Commercial Planning/Shared"

Run the command again when the form changes. It replaces the three files in the-form and changes nothing in the numbered folders. You can also make the folders by hand.

Check a file

This is the check of the example that ships with the release. --report also writes the report beside the file, under the same name with .check.txt in place of .json. For a workbook the name ends with .kpi-intake.workbook.check.txt.

py -m kpi_store.intake check kpi-intake/examples/crack-spreads-pricing.json --report
KPI intake check: Crack Spreads Pricing
...
Result: the intake is complete and signed.
This check changes nothing in the ontology. The Architect applies a complete intake by hand, with HOW-TO-UPDATE.md.
The report is also in crack-spreads-pricing.check.txt, beside the file.

For a file in the shared folder, name it where it is:

py -m kpi_store.intake check "S:/Commercial Planning/Shared/KPI-intake/2-ready-for-check/crack-spreads-pricing.kpi-intake.json" --report

The check changes nothing in the ontology. Add a complete KPI by hand, with the steps of HOW-TO-UPDATE.md in the release.

When the check says the pick lists are older than the release

A module of the ontology was released after the form was built. Rebuild the form and copy it to the shared folder again:

py -m kpi_store.intake build
py -m kpi_store.intake folders .
the intake pack is current; nothing was written
KPI-intake is current; nothing was changed

Here both commands found nothing to do. After a release, each prints the files it wrote.

Optional reference: where each part of the KPI is recorded

For readers who know the seven field groups of the KPI specification.

These groups are not the numbered sections of the form. Each number below opens that question in the form.

GroupWhat it holds, in plain wordsQuestions of the form
IdentityThe KPI's ID, its name and its data domain.An ID it already has: 3.6. Name: 2.1. Domain: 1.5
MeaningThe definition, and the business objective the KPI helps to track (the strategic objective).Definition: 2.2 to 2.4. Objective: 2.5
CalculationThe formula in words. The grain: what one individual value describes. The dimensions: the breakdowns people read it by.Formula: 3.1. Unit: 3.2. Grain: 3.8. How often, and the breakdowns: 3.3. Compared against: 3.4
AccountabilityThe owner, who is accountable. The steward, who maintains the definition. The status.Owner: 6.8. Steward: 6.9. Status: 3.9
AssuranceThe lineage: which tables and systems the values come from. The quality checks. The lifecycle: when it is reviewed and when it stops being used.Lineage: 7.1 to 7.4. Checks: 3.10. Review: 3.11
TargetsThe agreed limits (thresholds) and the dates they apply from.Limits: 3.12. Dates: 3.13
AccessThe data product, the view that gives the values (the semantic view), and an API: a way for a program to read the values.Data product: 6.6. View: 7.1. AI assistant or report: 7.8. API or file feed: 7.10

A question shows only when it applies, and only while the tab "KPI intake" is open. The status starts at "Draft". The form does not change it when someone signs.
