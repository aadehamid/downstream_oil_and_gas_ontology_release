How to use the KPI intake form

One form holds one KPI. You fill it in a browser, save it as one file, and put that file in a shared folder. The form works offline and sends nothing anywhere.

  1. IntakeThis form
  2. Govern & Link

  5. Monitor
  6. Change Management

The short version

Where one KPI's file goes, and who moves it.

  1. the-formThe Business analyst opens the form here and fills it with the business.
  2. Downloads"Save answers to file" puts the file here, on your own computer.
  3. 1-in-progressThe Business analyst moves the file here after every save.
  4. 2-ready-for-checkThe Business analyst moves it here when the form is filled and the business has signed.
  5. 3-checkedThe Architect moves it here when the check says it is complete.

The file is the record. The browser also keeps a draft, but only on your computer, so nobody else can see it. Save a file whenever you stop.

Set up once

One shared folder, with the same four folders for everyone.

Your team needs one folder that everyone can open, such as a folder on a shared drive. It is named KPI-intake and it always has these four folders in it.

Make the folders

The Architect makes the folders with one command, from the release's top folder. The dot at the end is the place. Write the place of your shared drive instead of the dot.

py -m kpi_store.intake folders .

You can also make the four folders by hand and copy the three files into the-form. When the form changes, the Architect runs the command again. It replaces the three files in the-form and changes nothing in the numbered folders.

The name of an answers file

Keep the name the form gives. It is the KPI's name in small letters, then .kpi-intake.json. For the KPI "Crack Spreads Pricing" the form proposes:

crack-spreads-pricing.kpi-intake.json

One KPI has one file. When you save again, put the new file in 1-in-progress in place of the older one. The request's date and each signature's date are inside the file, so the name needs no date.

The three buttons

They are at the bottom left of the form.

Save answers to file
Writes every answer, signature and comment of the form on screen into one file. Your browser puts the file in its download folder, which is usually Downloads. The form stays as it is, so you can go on.
Load answers file
Asks you for a saved file and shows its answers in the form. It replaces what is in the form and does not ask first. Save your work before you load another file.
Clear this form
Asks "Clear this form?" first. "Clear" empties the form on screen: every answer, signature and comment. "Cancel" keeps everything. A file you saved is not changed.

Three tabs of the form are forms: "KPI intake", "Domain activation" and "Process map request". Each button works on the form whose tab is open, and each form saves to its own file.

Fill in one KPI

From an empty form to a file in the shared folder.

Start a new KPI

  1. Open the-form in the shared folder and double-click kpi-intake-form.html. It opens in your browser.
  2. Look at question 2.1. If it shows another KPI's name, the browser has kept a draft of earlier work. Press "Save answers to file" if that work is not saved yet. Then press "Clear this form" and "Clear".
  3. Open "Request details" at the top and fill in the request's number and date.
  4. Answer the questions in order. Each question says who answers it and why it is asked, and shows an example answer.
  5. Where a question offers a list, choose from the list. You can choose an entry marked "new, not yet in the ontology". If the right answer is not in the list, choose "Not in the list". The form then says what happens next.
  6. Press "Save answers to file" when you stop.
  7. Open Downloads and move the file to 1-in-progress in the shared folder.

Your browser may ask where to save the file. Then choose 1-in-progress directly. If Downloads already holds a file of the same name, your browser may add a number such as (1) to the new one. Move the newest file and take the number out of its name.

Stop and go on later

The form keeps a draft in your browser as you type. Close the browser, open the form again on the same computer in the same browser, and your answers are back. The form says so:

Your unsaved draft was restored from this browser.

The draft has limits, so do not rely on it alone.

  • It is in one browser on one computer. A colleague, another computer and another browser do not have it.
  • It holds one KPI. When you clear the form or load a file, the earlier draft is gone.
  • A private window may not keep it, and it goes when someone clears the browser's data.

Go on from a saved file

Yes, you must load it. The form cannot find your saved files by itself. To go on from a file, on any computer:

  1. Open the form from the-form.
  2. Press "Load answers file" and choose the file in 1-in-progress.
  3. The form says "Loaded" and the file's name. Go on with the questions.
  4. Press "Save answers to file", and move the new file to 1-in-progress in place of the older one.

This is also how the work passes from one person to the next. Digital IT loads the same file to fill in section 7. Each signer's name and date go into the sign-off block of the same file.

Hand it over for the check

Each section's line counts what is left. When every section says "Required answers complete", and the Data Owner and the Domain Owner have signed, save one more time. Move the file from 1-in-progress to 2-ready-for-check and tell the Architect.

If you prefer Excel

kpi-intake-form.xlsx is the same form as a workbook, with the same questions and lists. Copy it to 1-in-progress first. Name the copy after the KPI and end the name with .kpi-intake.xlsx. Then fill in the yellow cells and save as usual. The check reads a workbook the same way as an answers file. Use one of the two for a KPI, not both: the HTML form cannot load a workbook.

After you save

The check, the signatures, and how the KPI gets into the ontology.

The Architect runs the check on each file in 2-ready-for-check. The check needs Python and the release folder, so the business does not run it. This is the check of the example that ships with the release:

py -m kpi_store.intake check kpi-intake/examples/crack-spreads-pricing.json --report
KPI intake check: Crack Spreads Pricing
...
Result: the intake is complete and signed.
This check changes nothing in the ontology. The Architect applies a complete intake by hand, with HOW-TO-UPDATE.md.
The report is also in crack-spreads-pricing.check.txt, beside the file.

For a file of your own, name it where it is. --report also writes the report beside the file, under the same name with .check.txt in place of .json. For a workbook the name ends with .kpi-intake.check.txt.

py -m kpi_store.intake check <your shared drive>/KPI-intake/2-ready-for-check/crack-spreads-pricing.kpi-intake.json --report

What "complete" means

  • Every required question that applies has an answer.
  • No answer sends the request somewhere else first: to a domain activation or to a process map request.
  • The KPI's name is not already a measure in the ontology.
  • Every signature the form needs has a name and a date.

The check lists each thing that is still open. If something is open, the Architect moves the file and its report back to 1-in-progress, and the Business analyst settles what the report lists.

Who signs

WhoWhat the signature saysWhen
Data OwnerThe KPI's definition is right.Every KPI
Domain OwnerThe KPI belongs to my domain.Every KPI
Domain Owner, a second timeI have decided between two definitions.Only when the check finds a conflicting definition

The Architect signs last: loads the file, types the name and the date, saves, and runs the check again with --report. When the result is "the intake is complete and signed", the Architect moves the file and its report to 3-checked.

How the saved answers are used

The check changes nothing in the ontology. The Architect reads the complete file and adds the KPI to the ontology by hand, with the steps of HOW-TO-UPDATE.md in the release. Some answers have no place in the ontology yet. They stay in the file, so keep every file in 3-checked.

If something goes wrong

Four things that happen, and what to do.

A file will not load

The form says "This file is not a KPI intake answers file" and gives the reason. Your answers on screen are not changed. Check that you chose a file whose name ends in .kpi-intake.json, and not the report or a workbook. If it is the right file, give it to the Architect.

A role, a system or another entry is missing from a list

Choose "Not in the list" and write its name. For some lists the form then points you to a smaller form, the process map request. Tell the Architect too. The Architect can add the entry to the form's lists. The form then offers it, marked "new, not yet in the ontology".

The check says the pick lists are older than the release

This one is for the Architect. A module of the ontology was released after the form was built. Rebuild the form and copy it to the shared folder again:

py -m kpi_store.intake build
py -m kpi_store.intake folders .
the intake pack is current; nothing was written
KPI-intake is current; nothing was changed

Here both commands found nothing to do. After a release, each prints the files it wrote.

The form opens with someone else's answers, or with an older KPI

The browser has restored a draft. If that work is not saved, press "Save answers to file" first. Then press "Clear this form" and "Clear", or load the file you want.
